## 改造约定

改本仓的进线、分流、工具、审批、工单、检索引用、安全门、Trace、评测或商家后台之前，**先打开** `view-work/spring-ai-crossborder-customer-service`，找到同一类能力，对照后再改 `spring-ai-crossborder-chatbot`。

1. **先看参考仓怎么串**：`Triage → Specialist → Safety Gate → Tool → Response`，以及高风险审批、人工接管同一会话、Trace / 评测回放。本地目录就是这份参考；和上游仓库不一致时，以本地 `view-work/spring-ai-crossborder-customer-service` 里的实现为准。
2. **再落到本仓**：对齐行为规格和边界。检索底座继续用本仓的 PGVector + ES + RRF + DashScope Rerank，不换成参考仓的检索实现。
3. **参考仓只读**：不改 `view-work/spring-ai-crossborder-customer-service`，禁止整仓合并，禁止把 OmniMerchant 的类或页面整段搬进来。按清单引入需要的行为，不搬不需要的租户、渠道和 Shopify 集成。

没先对照就改，工具白名单、审批门和人工接管容易和参考链路不一致。商城交易改造不看这个仓，商城每次先看 `view-work/SpringMall`。

## 0. 一句话目标

把「能查单 / 能检索 / 能建审批 / 能建工单」的 Agent 内核，补成：

> **买家进线 → 分流 → 安全门 → 工具/RAG（带引用）→ 高风险审批 → 人工接管同一会话 → 结单 → Trace/评测回放**

---

## 1. 跨境客服全流程（目标态）

```text
① 入口 Intake     买家 Widget / 公开客服页（无后台 JWT）
② 身份 Identity   查单邮箱/手机校验；后台账号 RBAC
③ 语言 Language   检测 + 可选入站/出站翻译（轻量证据即可）
④ 分流 Triage     意图 → specialist + 工具白名单
⑤ 安全门 Safety   注入/过长输入/越权工具拦截
⑥ 执行 Act        查单/物流/商品/政策 RAG（citation）
⑦ 审批 Approval   退货/退款/换货/改地址 → PENDING → 主管审批
⑧ 人工 Human      工单绑定 chatId，Inbox 回同一会话
⑨ 结单 Close      AI_WORKING / NEEDS_APPROVAL / HUMAN_ASSIGNED / RESOLVED
⑩ 评测 Eval       Trace 回放 + CONTRACT（路由 + 真实 tool 断言）
```

参考仓官方骨架：`Triage → Specialist → Safety Gate → Tool → Response → QA`。

### 2.4 明确不引入（全量也不搬）⛔

避免变成「假全渠道 / 假 SaaS」，面试难收口：

- 多租户 SaaS + MyBatis 租户插件 fail-closed
- Shopify / 企微 / 抖店真连接或复杂 Fixture
- MySQL 第二业务库、RocketMQ、Prometheus SLO 全家桶
- 把单体拆成 Omni 七模块
- GOLD 人工标注集、完整 SLA/CSAT/计费大盘
- GraphRAG、多 Agent 集群

## 4. 分阶段实施计划（全量）

### Phase A — 对话闭环可见（约 3～5 天）

**目标：** 买家侧能「看见」Agent 做了什么。

| 任务 | 说明 | 验收 |
|------|------|------|
| A1 引用卡 | `refundPolicyRAG` 结果经 SSE/旁路事件推前端；气泡下展示来源片段 | 问政策能点开/看到 citation |
| A2 审批单卡 | 写工具返回 `requestId` 展示「已创建审批 #id」 | 退货后对话内可见 PENDING |
| A3 Agent 记忆 | `AgentChatService` 挂 chatId 历史消息 | 「刚才那单」能续聊 |
| A4 Safety Gate | 注入关键词/过长输入直接拒答或转人工 | `C-SAFE` 从「路由过」变「真拦截」 |

**参考抄什么：** Omni 的 citation DTO 形态、`SafeGuardAdvisor` 思路；不抄 Redis 依赖。

### Phase B — 人工与状态闭环（约 5～7 天）

**目标：** 转人工不是死胡同。

| 任务 | 说明 | 验收 |
|------|------|------|
| B1 工单绑会话 | `t_ticket.chat_id`；escalate 写入当前 chatId | 后台点工单能打开对话 |
| B2 Inbox 回复 | 后台可发内部备注 / 对买家可见回复写入同一 chat | 人工接管后对话继续 |
| B3 状态机 | 会话/工单状态：`AI_WORKING` / `NEEDS_APPROVAL` / `HUMAN_ASSIGNED` / `RESOLVED` | 列表可按状态过滤 |
| B4 角色入口 | 公开客服页无需后台 token；`/admin/**` 读写皆鉴权 | 角色分离一眼可演示 |

**参考抄什么：** `InboxView` / 工单投影思路；缩水实现，不做 SLA。

### Phase C — 可观测与评测（约 4～6 天）

**目标：** 简历数字可复现、面试可回放。

| 任务 | 说明 | 验收 |
|------|------|------|
| C1 Trace 表 | `t_agent_run` / `t_agent_step`（分流、tool、耗时、错误） | `/admin/traces` 可点开一次对话 |
| C2 Eval 升级 | 进程内契约：路由 + 写工具必须 PENDING + FAQ 引用 + 翻译回退 | `ContractEvalRunner`，后台 `/admin/evals` |
| C3 RAG Workbench 轻量 | 模式开关 + 是否够回答 | `/admin/rag-workbench` |
| C4 密码与登录态 | BCrypt + HMAC JWT | `AdminAuthService` / `AdminJwtService` |

**参考抄什么：** `AgentTraceService`、`AgentEvalRunnerService` 的用例结构；规模缩到 30～50 条。

### Phase D — 跨境加分项（约 3～5 天，可与 C 并行）

**目标：** 「跨境」不只是名字。

| 任务 | 说明 | 验收 |
|------|------|------|
| D1 语种检测 | 入站消息检测 zh/en（或 lingua）写入 trace | 后台可见 sourceLang |
| D2 出站语言 | 按买家语言回答（prompt 约束即可，可不接翻译 API） | 英问英答、中问中答 |
| D3 翻译 Tool | 术语表命中则翻译，否则回退原文并记证据 | `translateSnippet` + `t_lang_event` |
| D4 政策双语 FAQ | classpath 中英退货 / 关税 / 物流时效 | `faq-zh.md` / `faq-en.md`，英问能引用英文块 |

**参考抄什么：** Omni 多语言「证据字段」；不强制整条中转英语管线。

## 5. 目标架构（改造后）

```text
[买家公开客服页]              [商家后台 /admin]
        │                            │
        ▼                            ▼
 AiCustomerServiceController    Admin* + Auth(JWT/BCrypt)
        │
        ├─ SafetyGate
        ├─ Orchestrator(allowlist)
        ├─ ChatMemory(chatId)
        ├─ ChatClient.tools(...)
        │     ├─ Order/Logistics/Product
        │     ├─ refundPolicyRAG → Hybrid+Rerank → citations
        │     ├─ Approval tools → PENDING
        │     └─ escalateToHuman → ticket(chatId)
        ├─ AgentTrace (run/step)
        └─ SSE：文本 + citation事件 + action事件
```

包结构建议（仍单体，不拆七模块）：

```text
com.quanxiaoha.ai.robot
  agent/          # 已有 + Safety + Trace + StateMachine
  commerce/       # 已有
  helpdesk/       # 扩展会话级 Inbox
  eval/           # 扩展真实 tool 断言
  i18n/           # 新建：语种检测（Phase D）
```

> 包名 `com.quanxiaoha` 可保留以免大搬家；对外项目名与作者已是 `spring-ai-crossborder-chatbot` / `lazysheep101`。

## 8. 验收清单（全流程 Demo 剧本）

按顺序能跑通即算「全量引入完成」：

1. **买家**打开公开客服页，英/中提问退货政策 → 回答带 **引用卡**  
2. 提供 `ORD-10001` + 邮箱查单 → 工具日志可见 `queryOrder`  
3. 申请退货 → 对话出现 **审批 #id**；状态 `NEEDS_APPROVAL`  
4. **主管**登录后台通过审批 → 订单状态变化  
5. 买家投诉要人工 → 工单 `HUMAN_ASSIGNED`，Inbox **打开同一 chat** 回复  
6. 结单 `RESOLVED`  
7. Traces 能回放本次分流与工具  
8. `mvn test` 中 `AgentContractEvalTests`：路由 + 写工具 PENDING 门禁 + 双语 FAQ + 翻译回退通过  
9. 注入类问题被 Safety Gate 拦截（不执行写工具）
