# 人工层

人工层把「转人工」接回买家正在看的那条会话。它不调用大模型。

代码在 `com.quanxiaoha.ai.robot.helpdesk`。转人工工具在 `agent/tool/EscalationTools.java`。

总览：[架构说明.md](../../架构说明.md)。

## 转人工

`escalateToHuman` 调用 `HelpdeskService.escalate`。

工单写入 `t_ticket`：

| 字段 | 值 |
|------|----|
| `ticket_no` | `TK-` 加一段随机大写 |
| `chat_id` | 当前会话。来自工具执行线程上的 `ToolAuditService.currentConversationId()` |
| `status` | `HUMAN_ASSIGNED` |
| `customer_contact`、`order_no` | 工具参数，可以空 |
| `subject` | 空则用「客户请求人工客服」 |

有 `chat_id` 时，`ConversationStateService.markHumanAssigned` 把 `t_conversation_state` 也写成 `HUMAN_ASSIGNED`。

`chat_id` 为空时工单仍然会建，但收件箱无法把回复送回 Widget。编排层的 `ContextBoundToolCallback` 负责在工具执行前把会话号放上当前线程，避免出现空的 `chat_id`。

## 收件箱

后台页是 `/#/admin/inbox`，接口在接入层，规则在这里。

| 动作 | 方法 | 效果 |
|------|------|------|
| 列表 | `HelpdeskService.list` | 可按状态过滤，按 id 倒序 |
| 接管 | `takeover` | 状态改为 `HUMAN_ASSIGNED`，写下处理人 |
| 回复 | `replyToChat` | 向 `t_cs_message` 插一条 `role=human`，`chat_id` 用工单上的 |
| 结单 | `resolve` | 工单和会话状态改为 `RESOLVED` |

工单没有 `chat_id` 时，回复直接失败，提示「工单未绑定会话，无法回复」。

回复正文会加上「【人工客服 名字】」前缀。买家 Widget 轮询 `GET /customer-service/chat/{chatId}/messages`，把 `human` 消息显示成人工客服，不显示成模型。

若回复时工单还不是人工接管或已解决，回复本身会把状态补成 `HUMAN_ASSIGNED`。

## 会话状态

类：`ConversationStateService`。四个值：

| 状态 | 含义 |
|------|------|
| `AI_WORKING` | 模型还在处理 |
| `NEEDS_APPROVAL` | 已有待审批单 |
| `HUMAN_ASSIGNED` | 人工已接管 |
| `RESOLVED` | 已结单 |

编排层负责前两个和转人工时的 `HUMAN_ASSIGNED`。结单只在这一层的 `resolve`。

## 消息表

买家问题、模型回答、人工回复都在 `t_cs_message`，用 `chat_id` 串起来。`meta_json` 里可以有引用、审批单或工单号。

内部测试台的历史在另一张表 `t_chat` / `t_chat_message`，不和买家工单混用。

## 这一层不做什么

- 不重新分流，不调用检索。
- 不审批退款。主管审批在交易层。
- 不代替 Widget 轮询。页面自己拉消息。
