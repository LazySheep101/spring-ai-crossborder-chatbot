# 交易层

交易层负责订单、客户、商品、物流查询，以及退货、退款、换货、改地址的审批门禁。后台登录也在这一层。

代码在 `com.quanxiaoha.ai.robot.commerce`。工具入口在 `agent/tool/OrderTools.java`、`LogisticsTools.java`、`ProductTools.java`。页面不直接调用这些类。

总览：[架构说明.md](../../架构说明.md)。

## 查单和身份

`CommerceService.queryOrder`：

1. 按订单号找 `t_order`。`#ORD-10001` 和 `ORD-10001` 都先规范成大写再查。
2. 用 `customerContact` 对 `t_customer` 的邮箱或手机。邮箱忽略大小写，手机按原样比对。
3. 客户不存在、没填联系方式、或联系方式对不上，返回未通过，不把订单明细交出去。

物流 `trackLogistics` 同样先过这道身份校验。没有运单时说明尚未发货，不编造单号。

商品 `searchProducts` 按名称、描述、SKU、分类模糊查 `t_product`，最多 10 条。这是只读，不校验身份。

## 写操作的门禁

类：`ActionGate`。`CommerceService.createAction` 只在门禁通过后插入 `t_commerce_action_request`。

三道同时成立才接受：

| 条件 | 不成立时 |
|------|----------|
| 订单存在 | `REJECTED`，不入库 |
| 请求里有邮箱或手机 | `REJECTED`，不入库 |
| 联系方式和订单客户一致 | `REJECTED`，不入库 |

通过后的状态固定是 `PENDING`。工具返回的文案是「已创建待人工审批请求，AI 不会直接改单或退款」。没有从工具路径把状态写成已退款或已改地址的分支。

| 工具 | 写入的 actionType |
|------|-------------------|
| `createReturnRequest` | `RETURN` |
| `requestRefundOrReplacement` | 参数里带 replace 时是 `REPLACEMENT`，否则 `REFUND` |
| `requestAddressChange` | `ADDRESS_CHANGE` |

工具成功后调用 `AgentSideChannel.addAction`。没有 `requestId` 的拒绝结果不会推成审批卡。

## 主管审批

`POST /admin/actions/{id}/review` 调用 `AdminAuthService.requireSupervisor`。

角色必须是 `supervisor`。种子账号里 `admin` 和 `supervisor` 的角色都是 `supervisor`，所以都能审批。`agent` 的角色是 `agent`，调用会被拒绝。

通过或驳回之后才由审批服务改订单状态。驳回不改订单。

## 后台登录

`AdminAuthService.login` 用 BCrypt 核对 `t_admin_user.password`。库里若还是明文，登录成功后升成 BCrypt。

`AdminJwtService` 签发 HMAC-SHA256。载荷只有用户名和过期时间，角色以数据库为准，不写进 Token。默认有效期见配置 `admin.jwt.ttl-hours`。

请求头可以是 `Bearer <token>`，也可以是裸 token。签名不对、过期、用户已被删，都是 401。

## 这一层不做什么

- 不决定这句话该进退货还是物流。那是编排层。
- 不给买家发 SSE。
- 不创建人工工单。那是人工层。
