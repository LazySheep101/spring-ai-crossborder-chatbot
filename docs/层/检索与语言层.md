# 检索与语言层

这一层回答两类问题：政策原文从哪来，买家说的是中文还是英文。它不查订单，也不改审批状态。

总览：[架构说明.md](../../架构说明.md)。

## 检索

政策工具是 `refundPolicyRAG`，在 `agent/tool/PolicyTools.java`。

检索底座是本仓自己的实现，不换成参考项目的检索：

| 步骤 | 类 | 做什么 |
|------|----|--------|
| 向量 | PGVector，表 `t_vector_store` | 按嵌入找近邻 |
| 关键词 | Elasticsearch | 按词找政策片段 |
| 融合 | `HybridRetrievalServiceImpl` | RRF 把两路结果合到一起 |
| 重排 | `DashScopeRerankServiceImpl` | 再排一次，得到最终片段 |

开关在配置 `rag.hybrid.*`、`rag.rerank.*`。`rag.agent.enabled=true` 时走工具，Advisor RAG 关掉，避免同一问检索两次。

内置中英 FAQ 在 classpath：

- `resources/knowledge/faq-zh.md`
- `resources/knowledge/faq-en.md`

政策工具把 FAQ 引用和检索引用合并。混合检索抛错时，仍然返回 FAQ，不把整次回答打成失败。

命中的片段通过 `AgentSideChannel.addCitation` 推给前端，Widget 在气泡下显示「政策引用」。

商家在 `/#/admin/knowledge` 分片上传文档。合并后异步向量化，列表里能看到状态。`/#/admin/rag-workbench` 调 `POST /admin/rag/debug`，可选 `vector`、`hybrid`、`rerank` 等模式，并标出够不够回答。`/#/admin/rag-debug` 会转到这个页。

知识库上传没有单独的人工审核流。向量化失败留在文件状态里，不自动改订单。

## 语言

| 类 | 作用 |
|----|------|
| `LanguageDetector` | 入站消息判 `zh`、`en`、`mixed` |
| `LanguageEvidenceService` | 写入 `t_lang_event` |
| `SnippetTranslator` | 术语表命中就翻译；否则原文加原因 `NO_TRANSLATION_API` |
| `TranslationTools.translateSnippet` | 把上面的能力暴露成工具 |

系统提示按语种要求英问英答、中问中答。原文语种和买家不一致时，可以调 `translateSnippet`。没有外接翻译 API。回退也记在 `t_lang_event`，后台 `/#/admin/multilingual` 能看到。

## 评测和这一层的关系

`eval/ContractEvalRunner` 在进程内检查路由、写工具必须是 `PENDING`、安全门、FAQ 引用和翻译回退。它不调用外部对话模型。后台 `/admin/evals/summary` 跑的就是这份契约。

评测不在买家请求的主链路上。买家发一条消息不会触发全量评测。

## 这一层不做什么

- 不凭检索结果直接创建退货单。退货仍要走交易层门禁。
- 不把 Elasticsearch 当成订单库。
- 不在没有翻译 API 时假装已经译好。失败就保留原文并记下原因。
