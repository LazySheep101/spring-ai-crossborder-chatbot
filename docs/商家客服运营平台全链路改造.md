## 1. 产品信息架构（三端分离）

```text
┌─────────────────┐   ┌──────────────────────┐   ┌────────────────────────────┐
│  买家端 Widget  │   │  内部对话测试台      │   │  商家运营后台              │
│  /#/widget      │   │  /#/  与 /#/chat/*   │   │  /#/admin/*               │
│  公开、无后台JWT │   │  研发/演示调试用     │   │  登录 + RBAC              │
└────────┬────────┘   └──────────┬───────────┘   └─────────────┬──────────────┘
         │                       │                             │
         └─────────── 同一 Agent SSE / 工单 / 审批 / Trace ─────┘
```

| 端 | 路由 | 用户 | 核心页面 |
|----|------|------|----------|
| 买家端 | `/widget` | 买家 | 咨询卡片：欢迎语、消息流、输入、状态 Tag |
| 测试台 | `/`、`/chat/:id`、`/customer-service/chat` | 研发/演示 | 侧栏历史、模型选择、知识库上传调试 |
| 运营后台 | `/admin/*` | 客服/主管 | 概览、Inbox、订单、审批、知识、Trace… |

原则：**买家不进后台；后台不装成聊天 Demo。**

## 3. 业务全链路（必须可演示）

```text
买家打开 /widget
  → 输入问题（可选填邮箱）
  → Safety Gate + Triage + Tools/RAG
  → 气泡展示：文本 / 引用卡 / 审批单卡 / 工单号
  → 高风险：创建 PENDING 审批
  → 转人工：工单绑定 chatId，状态 HUMAN_ASSIGNED
客服登录 /admin
  → Dashboard 看到待办
  → Inbox 打开同一会话回复
  → 主管在 Actions 审批
  → Trace 回放整条 run
  → 工单 RESOLVED / 会话结单
```

验收剧本（面试口述用）：

1. Widget 问「ORD-10001 到哪了」→ 校验邮箱 → 物流结果  
2. Widget 问退货政策 → 引用卡可见  
3. Widget 申请退货 → 审批卡 PENDING → 后台 Approve  
4. Widget 要求人工 → Inbox 接管并回复 → 买家消息流可见  
5. Trace 能看到 triage / tool / response

## 8. 边界复查（2026-10-29）

| 边界 | 结论 | 处理 |
|------|------|------|
| 三端路由隔离 | ✅ 已拆 `/widget` / 测试台 / `/admin` | — |
| 后台 JWT | ✅ 拦截器 + 前端路由守卫；401 清 token 回登录 | 已补 axios 401 |
| Widget 人工回复角色 | ❌ 曾显示成 AI | 已改为 `human` 气泡 |
| Widget 流式双气泡 | ❌ 列表项 + streaming 占位重复 | 已去掉占位层 |
| Widget 刷新丢历史 | ❌ chatId 在、消息不回放 | 开始咨询时 hydrate `/messages` |
| Dashboard→审批 query | ❌ `?status=PENDING` 不随路由变 | Actions 已 watch query |
| Inbox/Trace 双层 panel | ⚠ 作业台被白卡片套住 | flush 布局 |
| 知识库上传 | ✅ 后台直接分片上传、合并、删除 | 向量化仍走原异步任务 |
| 登录态 | ✅ HMAC JWT，重启后仍有效 | 不是 Spring Security 全家桶 |
| 管理端页脚链到 Widget/测试台 | 演示跳转保留 | 不视为买家越界 |
