# 使用层

使用层是浏览器里的三个入口。代码都在 `chatbot-vue3`。这一层负责展示和收集操作，不连接数据库，也不判断退款能不能过。

总览在仓库根目录 [架构说明.md](../../架构说明.md)。前端安装命令在 [chatbot-vue3/README.md](../../chatbot-vue3/README.md)。

## 三个入口

路由是 Hash。开发时页面在 Vite 上，例如 `http://localhost:5174/#/widget`。`#` 后面的路径不会请求后端。

| 入口 | 地址 | 谁 | 登录 | 页面文件 |
|------|------|----|------|----------|
| 买家咨询 | `/#/widget` | 买家 | 不要 | `src/views/widget/WidgetView.vue` |
| 内部测试台 | `/#/` | 研发 | 不要 | `src/views/Index.vue` |
| 测试台里的一条对话 | `/#/chat/:chatId` | 研发 | 不要 | `src/views/ChatPage.vue` |
| Agent 调试页 | `/#/customer-service/chat` | 研发 | 不要 | `src/views/CustomerServiceChatPage.vue` |
| 商家登录 | `/#/admin/login` | 客服、主管 | 登录页本身 | `src/views/admin/LoginView.vue` |
| 商家后台 | `/#/admin/...` | 客服、主管 | 要 | `src/views/admin/` 下各页，壳是 `AdminLayout.vue` |

买家进不了后台。没有 `admin_token` 时，路由守卫把 `/admin` 转到 `/admin/login`。

## 买家页做了什么

`WidgetView.vue`：

1. 开始咨询前可以填邮箱或手机、称呼。邮箱保存在页面上，随每次发送放进请求体字段 `customerContact`。
2. 发送 `POST /api/customer-service/chat/completion`，正文是 SSE。
3. 普通文本追加到气泡。`type=blocked` 显示拦截原因。`type=meta` 按 `metaKind` 显示政策引用、审批单号或工单号。
4. 每 5 秒请求 `GET /api/customer-service/chat/{chatId}/messages`，把新的人工回复补进消息流。

`chatId` 存在浏览器 `localStorage` 的 `widget_chat_id`。刷新后用这个 id 把历史消息拉回来。

## 商家后台做了什么

登录成功后，`localStorage` 里有三样：

| 键 | 内容 |
|----|------|
| `admin_token` | JWT |
| `admin_displayName` | 显示名 |
| `admin_role` | 角色 |

`src/api/admin.js` 把 Token 放进 `Authorization: Bearer ...`。接口返回 401 时，`src/axios.js` 清掉这三样并回到登录页。

后台导航和页面对应关系：

## 请求怎么离开浏览器

`src/axios.js` 的 `baseURL` 是 `/api`，超时 7 秒。

开发时 `vite.config.js` 把 `/api` 代理到 `http://localhost:8081`，并去掉前缀。所以前端写 `/api/admin/orders`，后端收到 `/admin/orders`。

买家对话的 SSE 不走这个 Axios 实例，它直接请求 `/api/customer-service/chat/completion`。代理规则相同。

## 这一层不做什么

- 不判断订单是不是这个人的。
- 不把退货直接改成已退款。
- 不决定本轮能调哪些工具。这些都在后端。
