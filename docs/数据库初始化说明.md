# 小智 AI · 数据库初始化说明

> 项目：`spring-ai-crossborder-chatbot`（小智 / 跨境智能 Agent）  
> 数据库：PostgreSQL + pgvector  
> 库名（dev）：`robot`（见 `application-dev.yml`）

---

## 1. SQL 文件位置

统一目录（**只改这里**，不要改 `target/classes/sql`）：

```text
spring-ai-crossborder-chatbot/chatbot-springboot/src/main/resources/sql/
├── init_all.sql          # ★ 一键全集：建表 + 种子（推荐手工初始化用这个）
├── ai_robot.sql          # 核心元数据表 + pgvector 扩展（启动自动加载）
├── commerce_agent.sql    # 电商 Agent 业务表（启动自动加载）
└── seed_demo_data.sql    # 演示种子 SQL（拆分维护；已并入 init_all.sql）
```

路径相对于后端模块：

`chatbot-springboot/src/main/resources/sql/`

一键脚本：

`...\sql\init_all.sql` = `ai_robot.sql` + `commerce_agent.sql` + `seed_demo_data.sql`（幂等）

---

## 2. 启动时谁加载什么

| 顺序 | 组件 | 脚本 | 说明 |
|------|------|------|------|
| `@Order(10)` | `RobotSchemaInitializer` | `classpath:sql/ai_robot.sql` | 对话 / 知识库文件 / 向量表 / 扩展，幂等 |
| `@Order(20)` | `CommerceSchemaInitializer` | `classpath:sql/commerce_agent.sql` | 电商表结构；表空时再 `seedIfEmpty()` 写演示数据，并升级后台明文密码为 BCrypt |

特性：

- 均为 `CREATE TABLE IF NOT EXISTS` / 冲突跳过，**可重复启动**。
- `seed_demo_data.sql` **当前未被 Initializer 自动加载**；需要时可在 DataGrip / `psql` 手工执行，或后续接到启动链路。
- 日常开发：起后端即可自动建表；库是新库时确保 PostgreSQL 已启动且账号能建库/建扩展。

## 4. 各脚本内容概要

### 4.1 `ai_robot.sql`（核心）

- 扩展：`vector`、`uuid-ossp`
- 主要表：
  - `t_ai_customer_service_file_storage` — 知识库上传分片元数据
  - `t_ai_customer_service_md_storage` — 已合并文档
  - `t_chat` / `t_chat_message` — 会话与消息
  - `t_file_chunk_info` — 分片信息
  - `t_vector_store` — pgvector 向量存储（与 Spring AI `table-name` 对齐）

### 4.2 `commerce_agent.sql`（电商 Agent）

- `t_customer` / `t_product` / `t_order` / `t_order_item` / `t_shipment`
- `t_commerce_action_request` — 退货/退款等待审批动作
- `t_tool_call_log` — 工具调用审计
- `t_ticket` — 工单
- `t_agent_run` / `t_agent_step` — Agent 运行轨迹
- `t_cs_message` / `t_conversation_state` — 客服消息与会话状态
- `t_admin_user` — 后台账号

### 4.3 `seed_demo_data.sql`（演示数据，手工可选）

- 后台：`admin`/`123456`（supervisor，可审批）；另有 `agent`/`agent123`、`supervisor`/`super123`（明文会升 BCrypt）
- 客户、商品、订单（如 `ORD-10001`）、物流、部分动作/工单等  
- 与 `CommerceSchemaInitializer.seedIfEmpty()` 目标一致，以**启动时 Java 种子**为准；SQL 文件便于空库手工灌数或对照。

## 5. 手工初始化（推荐一键）

PostgreSQL 容器就绪、库 `robot` 已创建后，在项目根目录执行：

```bat
docker exec -i PostgreSQL psql -U lazysheep101 -d robot < chatbot-springboot\src\main\resources\sql\init_all.sql
```

或 DataGrip 打开 `init_all.sql`，对 `robot` 库整文件执行。

拆分执行（等价）：

```bat
docker exec -i PostgreSQL psql -U lazysheep101 -d robot < chatbot-springboot\src\main\resources\sql\ai_robot.sql
docker exec -i PostgreSQL psql -U lazysheep101 -d robot < chatbot-springboot\src\main\resources\sql\commerce_agent.sql
docker exec -i PostgreSQL psql -U lazysheep101 -d robot < chatbot-springboot\src\main\resources\sql\seed_demo_data.sql
```

宿主机数据目录示例：`D:\2026-Knowledge\docker\PostgreSQL`（Docker 卷挂载，与 SQL 文件位置无关）。

> 维护约定：改表结构时同步改拆分文件，并重新合并/更新 `init_all.sql`；应用启动仍只读拆分文件，不读 `init_all.sql`。
