# 数据层

业务数据在 PostgreSQL，库名 `robot`，向量用 pgvector。政策关键词在 Elasticsearch。页面不直连这两个库。

总览：[架构说明.md](../../架构说明.md)。建库命令和启动时装载顺序见 [数据库初始化说明.md](../数据库初始化说明.md)。

本地账号、密码、模型 Key 只写在 `chatbot-springboot/src/main/resources/application-dev.yml`。公开仓库只提交 `*.example`。

## SQL 文件

目录：`chatbot-springboot/src/main/resources/sql/`。

| 文件 | 内容 |
|------|------|
| `ai_robot.sql` | 对话、知识库文件、向量表、pgvector 扩展 |
| `commerce_agent.sql` | 订单、工单、审批、轨迹、语言事件 |
| `seed_demo_data.sql` | 演示订单和商品 |
| `init_all.sql` | 上面三份合在一起，手工初始化用这一份 |

启动时 `RobotSchemaInitializer` 装 `ai_robot.sql`，`CommerceSchemaInitializer` 装 `commerce_agent.sql`。都是 `CREATE TABLE IF NOT EXISTS`，可以重复启动。电商表为空时才写入演示种子，并把后台明文密码升成 BCrypt。

## 表按谁使用分组

测试台对话，和买家客服不是同一套表：

| 表 | 内容 |
|----|------|
| `t_chat` | 测试台会话 |
| `t_chat_message` | 测试台消息 |

买家客服和人工：

| 表 | 内容 | 谁写 |
|----|------|------|
| `t_cs_message` | 买家、模型、人工客服的消息 | 编排层、人工层 |
| `t_conversation_state` | `AI_WORKING` / `NEEDS_APPROVAL` / `HUMAN_ASSIGNED` / `RESOLVED` | 编排层、人工层 |
| `t_ticket` | 工单，`chat_id` 指向买家会话 | 人工层 |
| `t_agent_run` | 一次客服运行 | 编排层 |
| `t_agent_step` | 安全门、工具、回复等步骤 | 编排层 |
| `t_tool_call_log` | 每次工具的参数、结果、耗时 | 编排层 |
| `t_lang_event` | 语种和翻译回退 | 语言层 |

交易：

| 表 | 内容 |
|----|------|
| `t_customer` | 客户邮箱、手机 |
| `t_order` | 订单 |
| `t_order_item` | 订单行 |
| `t_product` | 商品 |
| `t_shipment` | 物流 |
| `t_commerce_action_request` | 待审批动作，新建时状态是 `PENDING` |
| `t_admin_user` | 后台账号。角色 `supervisor` 可审批，`agent` 不可以 |

知识库：

| 表或索引 | 内容 |
|----------|------|
| `t_ai_customer_service_file_storage` | 上传文件和向量化状态 |
| `t_ai_customer_service_md_storage` | Markdown 存储 |
| `t_file_chunk_info` | 分片 |
| `t_vector_store` | pgvector 向量 |
| Elasticsearch 索引 | 政策关键词。地址在配置 `spring.elasticsearch.uris`，本地默认 `http://localhost:9200` |

## 演示数据

种子订单包括 `ORD-10001`。演示剧本里的买家邮箱是 `zhangsan@example.com`，必须和该订单客户一致，查单和退货才会通过。

后台三个账号见根目录 `README.md`。密码在首次登录或启动升级后以 BCrypt 存在 `t_admin_user`，不在本文重复列出哈希。

## 这一层不做什么

- 不保存多租户字段。表是单店的。
- 不把向量库当成订单库。查单只读 `t_order` 和 `t_customer`。
- 不在公开文档里记录数据库密码和模型 Key。
